### 문제
- 애플리케이션 로그 없이 서버가 죽고 다시 실행되는 이슈 발생

### 해결
- 긴급 대응으로 서버 스케일업을 진행
    - 문제 파악 로그를 얻기 위해 임시 조치
    - dynatrace를 사용하여 메모리 사용량 분석
    - OS 자체 OOM 문제로 판단
- jmap을 사용하여 문제가 되는 class 확인
    - LinkedBlockingQueue 기본 생성자가 Integer.MAX_VALUE 크기 큐 할당 
        - 메모리 과다 사용
        - 큐 크기를 100만으로 고정
    - HttpResponse 미반납 
        - 메모리 점유 증가
        - finally 블록에서 EntityUtils.consumeQuietly(response.getEntity()) 코드를 추가하여 완전히 자원 반납
        - 이후에 팀 리팩토링 기간에 try-with-resoureces로 변경

### 배운점
- JVM 메모리 분석에 대해 배울 수 있었습니다.
- 멀티스레드 환경에서 큐 크기 관리의 중요성에 대해 알게 되었습니다.
