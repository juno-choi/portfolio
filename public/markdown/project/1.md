### 해결
- 기존 BCrypt 암호화 알고리즘을 SHA-512로 교체 진행
  - Spring에서 제공하는 DelegatingPasswordEncoder를 사용하여 이후 2년마다 암호화 알고리즘을 변경할 수 있도록 구현
- 동시 접속 차단 기능 구현
  - 기존 구분값이던 token을 user_uuid와 mapping하도록 하여 1인 로그인 기능 구현
- 로그인 session 기능 구현 중 트러블 슈팅
  - 1시간 마다 세션을 수동으로 연장하도록 기능 구현 중 FE쪽에서 PC 시간 설정에 따라 서버의 시간 차이로 인해 시간이 다르게 표시되는 이슈 발생
  - NTP 개념을 도입하여 문제 해결
- 로그인 기록 기능 구현
  - 로그인 시간, 로그인 IP, 로그인 기기 정보를 저장하여 로그인 기록을 확인할 수 있도록 구현

### 배운점
- KISA 정책에 맞는 암호화 알고리즘 구현을 위해 salt 구현, 보안 강도(112비트 이상), 느린 해싱 알고리즘 등을 고려할 필요성을 알게 되었습니다.
- stateless한 token을 stateful한 token으로 변경하는 방법에 대해 고민해볼 수 있었습니다.
- Network Time Protocol을 통해 서버와 클라이언트의 시간 차이를 해결할 수 있다는 것을 알게 되었습니다.
