### 문제
- 4,500+ 라인 이상의 단일 클래스에 모든 비즈니스 로직 집중
- 하드코딩된 분기 처리로 인한 코드 가독성 저하
- 팀내 온보딩 난이도 증가

### 해결
- 도메인별 책임과 역할을 명확화
    - BookTime, BookTimeAdapter 등 핵심 로직의 도메인들을 객체로 분리
- 비즈니스 로직의 응집도 향상
- 디자인 패턴 적용을 통한 구조 개선
    - 전략 패턴: 골프장별 요구사항을 위한 하드코딩을 전략패턴으로 분리
    - 팩토리 패턴: 골프장별 ERP 시스템 구현체를 팩토리 패턴을 통해 생성
    - 어댑터 패턴: 외부 시스템 연동 추상화
    - 간단한 연동시에는 어댑터만 구현하여도 연동이 되도록 설계를 변경, 필요시 전략 패턴을 적용
- 점진적 개선
    - 골프장별 버전 관리를 통해 점진적 개선 적용
    - 테스트 코드 적용을 통해 기능 변경의 영향을 최소화

### 배운점
- 디자인 패턴을 적용하여 시스템의 유연성을 확보할 수 있다는 점을 배울 수 있었습니다.
- 점진적 개선을 적용하는 방법에 대해 고민해볼 수 있었습니다.
